Themes

Four themes: dark (default), light, sepia and dusk. A theme is a re-tuning of the tokens, not a different component set: 36 of the 39 tokens are overridden per theme (fonts stay shared).

How a theme is applied

A theme is a single attribute on the document element, html[data-theme="..."]. Omitting the attribute is the dark theme. theme.js owns the whole cycle:

StepWhat happens
PersistThe chosen theme is stored in localStorage["crossdeck-theme"]. Unknown or stale stored values fall back to the default rather than erroring.
First painttheme.js loads in <head> and applies the stored value before the body renders, so there is no theme flash.
SwitchCrossdeckTheme.set(value) validates against the four known themes, sets or removes the data-theme attribute (dark removes it), persists, and rewrites the in-prototype links. CrossdeckTheme.get() returns the current value or null.
Live syncSame-origin tabs hear the storage event and re-apply, so every open page switches together. The storage event also fires with a null key, which theme.js treats as "re-read both keys".
Fallback for split originsBrowsers that give each file:// page a unique origin (Firefox) cannot share storage: the theme and the colourblind mode also ride on the ?theme= and ?cb= URL parameters of in-prototype links, and the set methods keep those links current. A URL parameter also wins over storage when present, and is persisted on the way in.

The user-facing switch lives on the settings page, Appearance card: a select.input bound to CrossdeckTheme.set, initialised from CrossdeckTheme.get(). A second select on the same card drives CrossdeckCB.

The four themes

Dark (default, no attribute)

Near-black surfaces (#0e1116) with a one-step card lift. The only theme that uses inset top highlights (1px white at 2-3%) on its shadows for the raised edge, and the only one whose top bar has no shadow at all (--chrome-shadow: none). The accent is the brightest in the set: cyan #41d9f0 at 10.3:1 for the focus ring.

Light

White cards on a slightly deeper surface (#e9edf4) so the cards keep real presence, and the top bar sits on a white chrome layer with a soft drop shadow. Every role colour darkens to hold contrast on white: cyan becomes petrol #0a6f86, green #0e754f, amber #8f5705, violet #7233e0.

Sepia

A warm-paper light theme: cream surfaces (#faf7f0 cards on #ece5d8) with a petrol accent, #0c6b5c, so the app's identity survives the colour-temperature shift. The role palette shifts with the paper: olive-green ok, burnt-sienna warn, plum info.

Dusk

A mid slate-blue between dark and light: surfaces are a visible step up from dark's near-black (#1d2536) so the page reads as a night scene rather than a void, and the text is soft (#dbe3f2) rather than white. The only theme with its own chevron stroke: the shared #6b7484 measures 2.8:1 on dusk's card, under the 3:1 standard for UI components, so the token is re-tinted to #8fa0c0.

Contrast notes carried in the stylesheet

  • Tertiary text was lightened in v5 specifically to clear WCAG AA: v4's #6b7484 measured 3.70:1 on cards, under the 4.5:1 standard for normal text.
  • The editor page's kind pill uses --chip-text rather than --text-3 because dusk's #8b98b3 on dusk --chip-bg measures 4.14:1, still under 4.5:1.
  • Every colourblind mode's role-on-surface pairs clear 4.5:1 on the worst surface of its theme class and on the role's own tint; the prototype verifies this programmatically before release.

Modelling the themes in Avalonia

  • One base dictionary (dark) plus small override dictionaries per theme that redefine the same resource keys; merge order decides the winner, later dictionary wins.
  • Avalonia's ThemeVariant gives you the dark/light pair for free (FluentTheme already flips on it). Sepia and dusk have no built-in variant: register them as runtime-swappable dictionaries on Application.Current, or as resource keys the app swaps on change.
  • The prototype's single-attribute model (data-theme) has no direct Avalonia equivalent; the closest is a theme service that (re)merges the chosen dictionaries on change and persists the choice, mirroring CrossdeckTheme's get/set/persist/sync contract.
  • Verify the Avalonia 12 theme-variant resource syntax in the docs before relying on it; the 11-era patterns have drifted.
