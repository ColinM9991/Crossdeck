Components

Each component has its own page: a live example, rendered under the header selectors, alongside a full spec of its parts, tokens, states and behaviour. The values are the prototype's, quoted verbatim: foundation components from design-system.css, page components from each page's own <style> block. Each token's per-theme value is on the Tokens page.

Foundation components read only token keys, so they are correct in all four themes and all four colourblind modes; page-specific components use tokens only. Two house rules apply to everything here: one global focus ring (2px --cyan, 2px offset, on keyboard focus), and small icon buttons pad invisibly to a 44px hit target.

Foundation components

  • Top bar .topbarThe 56px band across every page: wordmark, active profile, connection state, unsaved changes, and the primary actions.
  • Buttons and links .btn, .linkEvery action in the app. Actions are buttons, never dead anchors.
  • Rail .rail, .rail-itemCross-page navigation: the 92px icon column on the left, which becomes a fixed bottom nav at 640 wide.
  • Columns and heads .col, .col-headThe page's content grid. Each page sets its own column widths (e.g. a 92 / 1fr / 420 three-pane layout); the columns are the scrollable panes and the heads are their title rows.
  • Tabs .tab-row, .tabSegmented page/section tabs. They render as pills on a bare canvas rather than bare text, because text tabs blend into the background in every theme.
  • Pills .chip, .status-pillShort labels in a fully rounded outline: the common pill shape. The base pill is the quiet tag; the status pill is the bolder version used in top bars and card heads.
  • Cards .card, .card-h, .card-b, .card-footThe content container: a header bar, a body region, and optional footer actions.
  • Key-value rows .kvLabel-left, value-right rows that fill card bodies and detail panes.
  • Stat cards .stat-row, .statA row of summary numbers: each card holds a big mono number over a small label.
  • Notes and callouts .note-line, .problem-line, .conn-note, .learn-noteAdvisory strips. The amber ones need attention; the neutral and cyan ones inform. All are single-line rows with an icon or dot lead-in.
  • Fields, inputs and segments .field-label, .input, .help, .segForm building blocks. Labels are tracked small-caps above; help text sits below; the segment control is the multi-option picker.
  • Detail and empty states .detail-head, .detail-empty, .empty-stateThe detail pane's title row, its no-selection placeholder, and the dashed no-contents panel for lists.

Page components

  • Settings page .nav-item, .set-row, .switchThe settings page's own controls: a section nav column, label-left / control-right rows, the switch, and the chevron select.
  • Variables page .var-row, .ref-box, .live-valueThe shared variable table, its detail column, and the write/read reference boxes.
  • Profiles page .profile-card, .import-zone, .open-actionThe profile list card and the detail pane's actions.
  • Devices page .device-card, .picker, .modalThe device list card, the add-device picker, the reassign modal, and the hardware-screen preview.
  • Editor page .binding-row, .device-card, .picker, .expr-listThe binding editor: device cards, the two-line binding rows, kind tags, the picker and the expression autocomplete.
  • Monitor page .event-row, .kind-chipsThe live event stream: a filter bar with kind pills and summary numbers, plus one row per input event.
