Colour roles

The system has four semantic colour roles. Components and themes never use a raw hue; they use the role tokens, which is what lets the colourblind modes repalette everything with 14 token changes.

RoleMeaningUsed byNow
--cyan familyAccent. The app's identity colour.Links, focus ring, active rail item, primary button, .active pills and segments, selected rows, learn notes.
--green familyOk / ready / connected..status-pill.ok, .chip.ok, live values, .stat success.
--amber familyWarn / attention / unsaved..status-pill.warn, .chip.warn, .note-line, .problem-line, unsaved counter, .stat.amber.
--violet familyInfo / provenance..chip.write (who writes a variable), write reference boxes, .stat info.

Each role has three tokens: the solid colour, a -line variant (the 1px border at reduced alpha) and a -bg variant (the tinted fill at low alpha).

Focus, selection and motion

  • Focus. One rule everywhere: :focus-visible { outline: 2px solid var(--cyan); outline-offset: 2px }. On the dark theme the ring measures 10.3:1 against adjacent surfaces (the 3:1 UI-component minimum is exceeded).
  • Text selection. background: var(--cyan-bg); color: var(--text) (the later rule wins over the base cyan-tint rule).
  • Motion. The only essential animation is the unsaved-counter pulse (0.45s ease, scale 1 to 1.15). Switches transition 0.15s. Everything non-essential is disabled under prefers-reduced-motion (durations forced to 0.001s, single iteration).
