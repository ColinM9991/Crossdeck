# Documentation rules

- Diagram colours: follow `docs/files/diagram-legend.md` and show the legend under the first diagram. The border says what a box is: red (`#c62f3a`, dark `#ff6a6f`) = hosted service, neutral grey = component, recessed muted = external (sim, hardware, OS, library), teal = UI. The fill says which hot path it is on: blue = input, amber = output, none = setup. Arrows: blue solid = input path, amber solid = output path, grey solid = creates or calls, grey dashed = event or signal. Red is reserved for hosted services, never errors. Reference page for style: `docs/device-paths.html`.
- Binary structures: any documentation of frames, packets, records, reports or headers states for every field its offset, its size (bits or bytes), its byte order, and whether it is fixed or variable length. Each structure gets a byte-layout table (`Offset | Size | Field | Encoding | Notes`) or diagram. Spell out type names, for example "u16 (2 bytes, little-endian)". Example hex comes after the table, never instead of it.
- Naming: never name other projects, repositories, tools or community apps (or their authors) in documentation, including folder names in this repository that come from other projects. Record the facts only. Where a fact needs a source label, use only SimAppPro or the generic marker "community". Remove any existing references to other project names you find on a page you edit.
